# 言策 Round 9 AI任务权威与源码UAT依赖闭环报告

## 定位

Round 9 是在 Round 8 全项目资产底账基础上的下一批源码检查点，重点关闭两个根因：

1. 记忆提取、媒体分析、人格改写长期没有独立权威任务，导致模型资格、路由、工作台和诊断使用不同名称或借用其他任务。
2. Windows 源码 UAT 只判断 `node_modules` 或 Electron 路径是否存在，无法识别半安装依赖，也没有稳定的多次重试与逐次日志证据。

本检查点不是正式 Windows 安装候选，也不声明真实平台、OpenRouter商业盲测或最终发布通过。

## 已完成的源码闭环

### 一、AI任务单一权威

新增并贯穿正式任务体系：

- `memory_extraction`：记忆候选提取和证据治理，不再借用 `fact_extraction`。
- `media_analysis`：联系人图片、语音、视频等媒体理解，不再与学习材料分析混用。
- `persona_rewrite`：Yeonhee Persona真人化改写和学习偏好应用，不再隐含在普通候选任务中。

已同步到：

- 共享任务常量；
- 模型运行Token与超时策略；
- 模型资格评估；
- OpenRouter能力分类与自动配置；
- 商业评估推荐路由；
- 回复质量资格；
- AI工作台任务目录；
- 系统诊断和核心任务就绪门禁。

同时修复 `material_analysis` 被错误判定为必须支持图片输入的问题。学习材料分析可以使用文本模型，真正媒体理解才要求相应多模态输入能力。

### 二、核心AI就绪状态真实性

系统中心新增独立核心AI任务门禁，至少检查：

- 翻译；
- 会话理解；
- 关系分析；
- AI导演；
- 快捷回复；
- 深度回复；
- 事实提取；
- 记忆提取。

没有模型、缺少主模型、模型不存在或未通过对应任务资格时，不能显示核心AI已就绪。AI工作台自检也不再因为“存在一条路由”就判全部任务通过。

### 三、Windows源码UAT依赖闭环

源码UAT权威启动链新增：

- 最多3次 `npm ci` 重试；
- 每次独立保存 stdout 与 stderr；
- 校验全部直接依赖的 `package.json`；
- 校验Electron真实可执行文件；
- `node_modules` 存在但包缺失、元数据损坏或Electron未解压时直接阻断；
- 启动报告记录依赖总数、完整数、安装模式、尝试次数和日志目录。

历史根目录多启动器继续隔离，不重新污染商业源码根。工程师使用唯一JS权威入口和npm脚本；最终Windows UAT材料包另行生成单一入口。
