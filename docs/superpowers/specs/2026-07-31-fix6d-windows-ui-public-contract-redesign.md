# Yance Batch40 FIX6D Windows UI 公共契约重构设计

## 1. 目标与边界

本轮只修复真实 Windows 截图和诊断文件确认的 UI 公共层缺陷。不得通过逐页覆盖、固定像素兜底、隐藏失败诊断、跳过后端或放宽门禁临时绕过。

生产修改范围限定为前端主题、导航、工作区布局、共享控件和布局诊断模块。Facebook、Telegram、WhatsApp、AI Provider 路由、SQLite 业务事务和消息队列不在本轮范围。

## 2. 已确认问题

1. 左侧主导航按钮尺寸、描边、间距和选中态过重，紧凑模式视觉拥挤。
2. 导航在 expanded、compact、hidden 间切换时，主工作区没有统一重算列定义；部分页面产生大面积空白、横向偏移或内容叠压。
3. 主题切换后品牌图标、导航选中态、按钮、边框和状态强调色来源不一致，旧青色残留在金色主题中。
4. AI 回复面板字号偏小、卡片密度过高，与中央会话区比例失衡。
5. 顶部通知条覆盖页面标题和操作区域，没有进入正常布局流。
6. 系统中心与设置页复用开关仍可能形成独立右侧轨道，标签、说明、控件关联弱。
7. 系统诊断的“路由自适应布局”在当前可见页面之外逐个切换 class 后立即读取 computed style，受到工作区显示契约、异步渲染和原路由恢复方式影响，产生九个“工作区未显示”误报。诊断文件记录当前视图为 theme、1920×1032、DPR 1，但九个工作区均被判定未显示，说明诊断探针与真实路由权威不一致，而不是九个页面同时消失。
8. 页面间圆角、边框层级、按钮高度、字号和背景层级没有统一密度契约。

## 3. 方案选择

采用“统一主题令牌 + 统一布局状态机 + 统一组件密度 + 权威诊断探针”的公共层重构。

不采用以下方案：

- 在各页面末尾追加 `!important` 覆盖；该方式继续扩大层叠冲突。
- 只调整截图中可见像素；该方式无法覆盖 100%/125%/150% DPI 和不同窗口宽度。
- 将诊断失败改成忽略或 warn；该方式掩盖真实布局状态。

## 4. 主题令牌权威

### 4.1 语义令牌

新增或统一以下语义令牌，组件不得直接绑定特定主题色：

- `--ui-brand-accent`
- `--ui-brand-accent-soft`
- `--ui-nav-active-surface`
- `--ui-nav-active-border`
- `--ui-nav-icon-color`
- `--ui-control-border`
- `--ui-focus-ring`
- `--ui-panel-surface-1/2/3`
- `--ui-text-primary/secondary/muted`

现有品牌 SVG 使用 `currentColor` 或主题遮罩输出；不得在组件 CSS 内写死青色、金色或固定 RGB。

### 4.2 主题切换

主题权威在一次原子更新中同步：根节点主题属性、语义令牌、品牌图标、导航状态和 computed audit。切换后不得保留上一个主题的组件颜色。

## 5. 工作区布局状态机

### 5.1 状态模型

布局只由以下状态决定：

- `navMode`: expanded | compact | hidden
- `contactMode`: normal | compact | hidden
- `aiVisible`: true | false
- `viewportBand`: wide | desktop | narrow | mobile
- `density`: comfortable | compact

公共函数计算根网格列，不允许页面 CSS 单独重写根 `.app` 列定义。

### 5.2 列宽原则

- 每个可伸缩内容列使用 `minmax(0, 1fr)`。
- hidden 列必须从网格中真正移除，不保留空槽。
- compact 导航使用稳定点击区域和居中图标，不依赖绝对定位。
- 路由页面统一占据 nav 后的全部可用区域。
- AI 面板关闭后中央会话区立即回流。
- 组合状态在 100%/125%/150% DPI 下不得产生横向滚动、标题裁切或控件重叠。

## 6. 导航与共享控件

### 6.1 主导航

主导航使用共享尺寸变量：宽度、按钮高度、图标框、组间距、圆角和边框强度。选中态只使用一层背景、一层边框和单一强调标记，禁止多重发光和粗描边叠加。

### 6.2 AI 面板

AI 面板设定最小可读字号、卡片垂直节奏和最大信息密度。快捷按钮允许换行，底部主操作保持一致高度。面板宽度由布局状态机提供，不由页面内部固定宽度控制。

### 6.3 设置开关

开关行统一为同一卡片内的“标签—说明—控件”布局。宽屏可为三列，窄屏转为两行；控件不得形成脱离语义内容的独立右轨。

### 6.4 通知条

全局通知进入正常布局流或专用 overlay 安全区，必须避开窗口控制区、页面标题和主要操作；多条通知需堆叠且可关闭。

## 7. 路由诊断权威

### 7.1 探针执行

诊断器不得直接修改 class 并立即读取。它必须调用 `YanceWorkspaceRouteAuthority.applyRoute`，等待至少两次 animation frame 和路由工作区 ready 条件，再采集 display、尺寸、溢出、标题流和可见性。

### 7.2 状态保存与恢复

探针开始前保存：

- 当前逻辑 view；
- 根节点 route class；
- nav/contact/AI 布局状态；
- 活动元素和滚动位置。

探针结束后通过路由权威恢复，不直接赋值完整 `className`。任何路由失败应输出具体 route、预期 class、实际 active views 和 workspace computed metrics。

### 7.3 判定规则

“工作区未显示”只有在目标路由已由 authority 确认激活、ready 条件满足后仍不可见时才成立。探针自身超时、路由冲突或渲染未完成应单独报告，不得误判为页面布局失败。

## 8. 测试策略

先增加失败测试，再修改生产代码：

1. 主题切换后品牌、导航、按钮均使用同一语义令牌。
2. nav expanded/compact/hidden × AI open/closed 的根网格契约。
3. 隐藏导航不保留空列，主工作区宽度增长。
4. 共享开关行在宽屏与窄屏保持标签关联。
5. 通知条不覆盖标题与窗口控制安全区。
6. 诊断探针必须通过 route authority，并在 ready 后测量。
7. 诊断恢复逻辑不破坏原路由和布局状态。
8. 1920×1032、DPR 1 的九路由诊断不再全部误报未显示。
9. 现有 Batch14、43 项主题布局、66 项 focused、111 项 UI prelaunch 全部继续通过。

## 9. Windows UAT 验收矩阵

真实 Windows 重新截图：

- 常规模式与空白隔离模式；
- 100%、125%、150% DPI；
- nav expanded、compact、hidden；
- AI 面板打开和关闭；
- 会话中心、AI 工作台、统一账号中心、系统中心、设置与恢复、主题与外观；
- 主题切换前后品牌图标与组件强调色；
- 系统诊断九个路由全部为真实结果；
- 多次切换页面和主题后无颜色残留、空列、叠压或横向滚动。

## 10. 完成门禁

只有以下条件同时满足才可生成新的 UI 复验包：

- 新增回归测试完成红—绿验证；
- 全部既有 UI/主题/布局门禁通过；
- 生产 CSS 无新增硬编码主题色；
- `git diff --check`、Node 语法和 CSS 解析通过；
- 最终 ZIP 反向解包复跑一致；
- Windows UAT 仍保持 false，直到用户提交新的实机截图证据。
