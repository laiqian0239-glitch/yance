## 1. 产品定位

言策是面向欧洲、日本、韩国用户的交友与关系沟通 AI 回复大脑，不是 CRM、客服或销售产品。

必须完整保留且不得退化：

- 现有回复风格；
- 现有导演模式；
- Persona 与 Style Genome；
- 自然、成熟、真实的女性表达；
- 多候选回复；
- 关系记忆；
- AI 学习成长；
- 模型路由；
- 翻译冻结；
- 发送与审计。

开源移植只能增加成熟度、稳定性、可见性、恢复能力和易用性，不能删减现有能力。

## 2. 双语消息显示（选择 A）

收到的消息气泡：

1. 中文翻译为主行，默认完整显示；
2. 原文为次行常显，可单独折叠；
3. 原文与译文独立保存，互不覆盖；
4. 折叠只改变显示，不影响 AI、搜索和审计；
5. 翻译中、失败、过期必须明确标记。

联系人/会话列表：

- 主预览固定显示翻译后的中文；
- 原文不作为主预览；
- 辅助显示 `DE / EN / JA / KO`、平台、账号、时间和翻译状态；
- 翻译中显示“正在翻译……”；
- 翻译失败显示“翻译失败 · 查看原文”。

消息、翻译与发送冻结必须由同一版本化对象表达，至少包含：

```text
messageId
conversationId
direction
sourceText
sourceLanguage
targetLanguage
translatedChinese
translationStatus
translationExpiresAt
draftRevision
translationVersion
translationBasedOnDraftRevision
manualEdit
manualEditBaseTranslationVersion
modelRouteReceipt
outboundFrozenText
outboundFrozenBytesSha256
frozenDraftRevision
frozenTranslationVersion
```

- `direction` 必须区分入站与出站，`conversationId` 与 `messageId`/草稿标识必须绑定真实会话作用域；
- `translationStatus` 至少区分 pending / ready / failed / stale / expired；
- 每次中文意图变化必须原子递增 `draftRevision` 并把旧译文标记为 stale；
- 翻译结果必须记录其请求时的 `translationBasedOnDraftRevision`，迟到结果不得覆盖当前草稿，只能作为不可发送审计证据保留；
- 人工修改必须记录编辑者、时间和基于的翻译版本，并原子递增 `translationVersion`；
- `modelRouteReceipt` 必须绑定模型资格、提供者路线、策略版本与结果版本，不得由界面临时选择替代。

## 3. 双语发送编辑器（选择 A）

```text
上层：中文意图编辑区
下层：目标语言实时译文
发送：用户确认后冻结的目标语言文本
```

约束：

- 中文草稿和目标语言译文分别保存；
- 译文可人工修订并标记“人工修改”；
- 中文意图变化后，旧译文立即过期；
- 翻译失败或目标语言不确定时阻止发送；
- 冻结前必须以一次原子比较并交换校验当前 `draftRevision`、`translationVersion`、`translationBasedOnDraftRevision`、ready 状态、未过期状态和模型路由收据；任一字段不匹配即拒绝冻结；
- 冻结记录必须保存目标语言、最终文本字节摘要、`frozenDraftRevision`、`frozenTranslationVersion` 和模型路由收据；
- 发送前再次原子校验冻结元组与字节摘要，发送只能读取不可变冻结记录，不能读取仍会变化的实时译文；
- 支持欧洲语言、日语、韩语的敬语、称谓和文化表达检查；
- 学习分别记录中文意图、机器译文和最终发送文本。

## 9. 跨平台身份合并（选择 A）

使用 `IdentityMergeAuthority`：

- 强证据允许自动关联；
- 弱证据由 AI 提议；
- 有歧义必须用户确认；
- 所有合并可预览、撤销、拆分并显示证据。

可自动关联的强证据：

- 已验证且完全一致的手机号或邮箱；
- 平台稳定身份映射；
- 用户通讯录明确绑定；
- 用户此前确认的关联；
- 可验证的账号迁移或设备凭据。

不得单独触发自动合并：

- 姓名相似；
- 头像相似；
- 所在地相同；
- 年龄相近；
- 聊天内容相似；
- AI 判断“像同一个人”。

合并不得删除原平台身份、混合消息时间线或静默覆盖冲突。拆分必须通过正式操作恢复身份、记忆/学习作用域和索引。

## 11. 跨平台关系时间线（选择 A）

统一高层关系时间线汇总：

- 共同经历；
- 重要日期；
- 明确承诺；
- 关系阶段变化；
- 关键互动；
- 冲突与修复；
- 用户确认事实。

每个事件必须保留：

- 来源平台；
- 发送账号；
- 原会话；
- 原消息；
- 形成时间；
- 跳回原消息的入口。

各平台消息时间线仍保持独立。事件可修正、合并、撤销和恢复，但恢复不得自动重新显示已失效事件。

失效事实采用分层保留与删除边界：

- 原始消息正文只由原会话消息存储持有，关系事件默认只保存可审计引用、来源摘要与必要派生字段，不复制一份永久正文；
- 普通撤销后，事件内容进入最多 30 天的加密撤销窗口并从正常界面、搜索、召回和模型上下文中移除；窗口内恢复必须由用户明确执行；
- 30 天后删除失效事件内容，只保留最长 365 天的最小审计墓碑：事件标识、来源引用摘要、失效时间、执行者、动作类型与策略版本；墓碑不得包含原消息正文、直接联系人标识或可用于继续推断关系的内容；
- 用户撤回同意、删除联系人/账号或提出适用的删除请求时，跳过撤销窗口并删除正文与派生内容；除非存在已记录的法律或审计保留依据，只能保留上述最小墓碑；
- 法律或审计例外必须记录依据、范围、责任人、开始与到期时间，并至少每 90 天复核；到期后立即回到普通删除规则；
- 30 天后如需恢复，只能在原消息仍被合法保留且用户再次明确确认时重建；仅凭审计墓碑不得恢复正文或让失效事件重新可见。

## 12. AI 推断进入关系时间线（选择 A）

- AI 推断先进入“待确认洞察”；
- 用户确认后才能成为正式关系事实；
- 低风险的情绪、聊天节奏分析可临时展示；
- 临时分析必须自动过期；
- 即使置信度高，也不得绕过确认直接晋升永久关系事实；
- AI 推断必须显示置信度、依据和新鲜度。

### Vercel AI SDK + LiteLLM Sidecar

用于统一模型调用和供应商路由。言策继续保留任务分类、模型资格、超时、取消、late-result、成本、发送和审计权威。

模型路由的数据出境边界必须由 `ExternalModelProviderPolicy` 冻结并失败关闭：

- 言策进程调用同机 LiteLLM Sidecar 不构成外部提供者出境；Sidecar 调用本地模型也不出境；只有 Sidecar 向第三方模型端点发起请求时才构成数据出境；
- 每条模型路线必须标记为 `LOCAL_ONLY`、`EXTERNAL_REDACTED` 或 `EXTERNAL_BLOCKED`，并绑定经用户批准的有序 `orderedProviders`；本快照不按名称预授权任何外部提供者，空列表即禁止出境；
- 外部路线只允许使用经过认证且证书校验开启的加密传输；跨主机的言策与 Sidecar 通道必须使用双向认证或等强度工作负载身份；
- 出境前必须移除平台账号、手机号、邮箱、地址、真实联系人标识、无关原消息、完整关系记忆和密钥；只发送完成当前任务所需的最小片段，并使用租户内不可逆假名标识；
- prompt 只可携带已批准的模板版本和最小任务上下文；关系记忆必须逐条经过任务相关性与敏感级别过滤，默认不出境；
- 租户数据、缓存、日志、向量空间与速率限制必须隔离；任何跨租户复用或共享上下文均禁止；
- 外部提供者必须处于不训练、零保留或经用户明确批准的等价合同模式；无法证明该模式、数据区域或删除能力时，该路线不具备模型资格；
- 提供者密钥只能由言策凭据托管或 Sidecar 运行时注入，禁止进入浏览器、prompt、日志、回执正文或候选分支；
- 每次外部调用必须生成不可变路由回执，记录策略版本、路线类别、提供者/模型、区域、出境数据类别、脱敏动作、租户、时间、成本和结果状态；审计记录不得保存敏感明文。

## 15. 后续默认决策协议

助手标注的“推荐方案”始终是非约束建议，在明确用户批准写入 `DecisionApprovalRecord` 前不得成为设计、实现、迁移或门禁默认值。批准记录必须包含批准者、决策标识、精确范围、绑定的设计修订、批准时间和允许的后续动作；范围外事项仍视为未批准。

只有完全可逆、无数据或权限副作用的展示细节可以在既有批准边界内自动采用，例如已批准区间内的面板初始宽度、间距、图标位置或动画时长；这些默认值必须可即时恢复且不得改变持久数据、调用路线或发送结果。

以下事项永远不得由助手推荐自动批准：

- 身份合并、联系人/会话权威或记忆作用域；
- 数据保留、删除、同意、训练或数据出境；
- 模型/提供者路由、密钥、租户隔离或审计边界；
- 许可证、来源、复制、分发或第三方代码引入；
- 分支授权、治理门禁、发布、生产、迁移与回滚；
- 翻译冻结、发送身份、发送文本或任何发送行为；
- 会删除、降低或不可逆改变现有功能的决定。

没有相应批准记录时，系统必须保留当前已批准行为或停止该项工作，不得把“推荐方案”解释为默许。

- 模块映射；
- 状态机；

实施采用一个迁移窗口、一个实施分支、多个普通 checkpoint 提交：

1. 基础与设计令牌；
2. Product Shell；
3. 会话和联系人；
4. AI 回复大脑；
5. 通知与导入声音清单（125 个现有候选音频资源文件）；

7. 数据迁移与闭环。

“125 个导入声音”仅指冻结迁移清单中的 125 个现有候选音频资源文件，不等于 125 个新功能、125 个稳定 sound ID 或自动分发许可。每个文件必须记录原始来源路径、内容摘要、MIME/编码、时长、稳定 sound ID 映射、重复/别名关系、许可证、署名要求与分发资格。它与现有 136 个 stable sound IDs 的对应关系必须逐项显式记录；多个 ID 可映射同一文件，缺失、别名和禁止分发项不得用占位音频静默补齐。未完成逐文件来源与许可核验前，只能盘点和本地预览，不能随产品分发。

禁止 amend、rebase、force push、巨型不可验证提交或弱化门禁。
