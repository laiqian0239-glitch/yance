- 状态：设计冻结快照，尚未写入 GitHub

- 核心原则：成熟开源能力优先；言策保持唯一产品、数据、AI、学习、模型路由、发送与持久执行权威；禁止临时绕过，必须底层重构。

## 1. 产品定位

言策是面向欧洲、日本、韩国用户的交友与关系沟通 AI 回复大脑，不是 CRM、客服或销售产品。

必须完整保留且不得退化：

- 现有回复风格；
- 现有导演模式；
- Persona 与 Style Genome；
- 自然、成熟、真实的女性表达；
- 多候选回复；
- 关系记忆；
- AI 学习成长；
- 模型路由；
- 翻译冻结；
- 发送与审计。

开源移植只能增加成熟度、稳定性、可见性、恢复能力和易用性，不能删减现有能力。

## 2. 双语消息显示（选择 A）

收到的消息气泡：

1. 中文翻译为主行，默认完整显示；
2. 原文为次行常显，可单独折叠；
3. 原文与译文独立保存，互不覆盖；
4. 折叠只改变显示，不影响 AI、搜索和审计；
5. 翻译中、失败、过期必须明确标记。

联系人/会话列表：

- 主预览固定显示翻译后的中文；
- 原文不作为主预览；
- 辅助显示 `DE / EN / JA / KO`、平台、账号、时间和翻译状态；
- 翻译中显示“正在翻译……”；
- 翻译失败显示“翻译失败 · 查看原文”。

数据对象必须独立：

```text
sourceText
translatedChinese
outboundFrozenText
```

## 3. 双语发送编辑器（选择 A）

```text
上层：中文意图编辑区
下层：目标语言实时译文
发送：用户确认后冻结的目标语言文本
```

约束：

- 中文草稿和目标语言译文分别保存；
- 译文可人工修订并标记“人工修改”；
- 中文意图变化后，旧译文立即过期；
- 翻译失败或目标语言不确定时阻止发送；
- 发送前冻结目标语言、文本字节、翻译版本、模型路由收据；
- 支持欧洲语言、日语、韩语的敬语、称谓和文化表达检查；
- 学习分别记录中文意图、机器译文和最终发送文本。

## 4. AI 回复大脑停靠方式（选择 A）

- 默认停靠右侧；
- 标准宽度：420–560px；
- 可调范围：360–760px；
- 中央聊天区最小宽度：520px；
- 可一键隐藏；
- 专注模式扩展到约半屏；
- 窄窗口自动转为覆盖式 Sheet；
- 调宽、隐藏或切换面板不能取消正在执行的 AI 任务；
- 重新打开后恢复候选、导演、风格、学习与模型路由状态。

## 5. 联系人详情栏与 AI 大脑（选择 A）

使用统一 `RightDockStateMachine`：

- 宽屏：联系人详情栏与 AI 大脑可同时停靠；
- 标准窗口：共用右侧区域，以“联系人 / AI 大脑”标签切换；
- 窄窗口：均转为覆盖式 Sheet；
- 标签切换不得清空状态、滚动位置、候选或导演上下文；
- 事实、AI 推断、关系记忆必须分区显示。

## 6. 左导航与会话列表（选择 A）

使用统一 `LeftDockStateMachine`：

```text
应用导航：expanded / compact / hidden
会话列表：visible / hidden / overlay
```

- 两者可分别隐藏；
- 会话列表建议宽度 280–520px；
- 隐藏后中央聊天区立即回流；
- 保留明显入口和快捷键；
- 当前会话、搜索、筛选、滚动位置不得丢失；
- 窄窗口转为覆盖式面板。

## 7. 统一多平台会话列表（选择 A）

所有平台进入同一会话中心：

- WhatsApp；
- Telegram；
- Signal；
- LINE；
- KakaoTalk；
- Instagram；
- Messenger；
- 其他经授权连接器。

默认按最近有效活动排序。平台只作为图标、账号和筛选条件，不建立平台专属聊天页面。

智能视图：

- 全部；
- 未读；
- 置顶；
- 最近；
- 平台；
- 账号；
- 关系分组。

状态必须可见：

- 草稿；
- 发送失败；
- 离线队列；
- 静音；
- 置顶；
- 未读；
- @提及；
- 翻译状态。

大列表采用成熟虚拟列表能力，恢复筛选和滚动位置。

## 8. 同一联系人跨平台呈现（选择 A）

- 统一联系人身份；
- 各平台会话仍保持独立时间线；
- 联系人详情统一汇总关系、记忆、事件和全部渠道；
- 支持“按联系人分组”视图；
- 草稿、未读、发送身份、回执和滚动位置仍属于各自会话；
- 联系人级记忆和学习可共享；
- 平台专属昵称、语言、文化和风格可覆盖；
- 每个候选回复必须明确目标平台与发送账号。

## 9. 跨平台身份合并（选择 A）

使用 `IdentityMergeAuthority`：

- 强证据允许自动关联；
- 弱证据由 AI 提议；
- 有歧义必须用户确认；
- 所有合并可预览、撤销、拆分并显示证据。

可自动关联的强证据：

- 已验证且完全一致的手机号或邮箱；
- 平台稳定身份映射；
- 用户通讯录明确绑定；
- 用户此前确认的关联；
- 可验证的账号迁移或设备凭据。

不得单独触发自动合并：

- 姓名相似；
- 头像相似；
- 所在地相同；
- 年龄相近；
- 聊天内容相似；
- AI 判断“像同一个人”。

合并不得删除原平台身份、混合消息时间线或静默覆盖冲突。拆分必须通过正式操作恢复身份、记忆/学习作用域和索引。

## 10. 联系人详情栏（选择 A）

默认显示“关系概览”：

```text
人物与关系摘要
关系时间线
记忆
渠道
AI 推断
```

首屏：

- 姓名、备注、头像；
- 关系阶段；
- 主要语言与文化背景；
- 最近互动；
- 当前聊天氛围；
- 重要日期；
- 全部平台与账号；
- 信息新鲜度。

电话、邮箱、地址等放在“渠道与资料”，不占首屏。

平台事实、用户确认事实和 AI 推断使用不同视觉标识。每条记忆显示来源、形成时间、最后验证时间和作用范围。

## 11. 跨平台关系时间线（选择 A）

统一高层关系时间线汇总：

- 共同经历；
- 重要日期；
- 明确承诺；
- 关系阶段变化；
- 关键互动；
- 冲突与修复；
- 用户确认事实。

每个事件必须保留：

- 来源平台；
- 发送账号；
- 原会话；
- 原消息；
- 形成时间；
- 跳回原消息的入口。

各平台消息时间线仍保持独立。事件可修正、合并、撤销和恢复；失效事实保留历史，不物理抹除。

## 12. AI 推断进入关系时间线（选择 A）

- AI 推断先进入“待确认洞察”；
- 用户确认后才能成为正式关系事实；
- 低风险的情绪、聊天节奏分析可临时展示；
- 临时分析必须自动过期；
- 即使置信度高，也不得绕过确认直接晋升永久关系事实；
- AI 推断必须显示置信度、依据和新鲜度。

## 13. 开源项目能力映射

### Chatwoot

用于：

- 会话列表；
- 联系人列表；
- 未读与消息状态；
- 消息时间线；
- 附件与引用；
- 联系人侧栏；
- loading / empty / offline / error 行为。

只移植成熟交互与行为合同；不得引入 Chatwoot Vuex、API、Router、联系人或会话权威；`enterprise/**` 排除。

### Monica

用于重要日期、互动、共同经历、关系事件模型。

### Graphiti

用于时间事实、来源、失效、关系召回 Sidecar。

### ConvoKit

用于互动节奏、语言协调和对话分析。

### Cytoscape.js

用于统一关系图展示。

### SillyTavern

用于 Persona、World Info、Prompt Manager、上下文装配行为合同。

### LangGraph.js

用于理解、召回、规划、多候选、人工确认、checkpoint。

### Vercel AI SDK + LiteLLM Sidecar

用于统一模型调用和供应商路由。言策继续保留任务分类、模型资格、超时、取消、late-result、成本、发送和审计权威。

### Langfuse + Promptfoo + Argilla + DSPy

用于学习证据、回归评测、人工反馈和离线优化。永久学习晋级必须有证据、用户同意、影子验证和回滚。

### UI 与桌面基础

- shadcn-vue + Reka UI；
- TanStack Query / Table / Virtual；
- XState；
- Tiptap OSS Core；
- i18next；
- Lucide；
- ECharts；
- Storybook；
- Playwright；
- axe-core；
- MSW；
- Mattermost Desktop 的 Electron 通知、托盘、badge、deep link、窗口唤醒、权限和诊断模式；
- Howler.js 用于声音预览、播放、音量、停止和资源释放，最终分发仍需逐文件来源与许可。
