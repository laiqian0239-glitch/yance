## 二、问题与修复

### FIX16-001｜内部账号 ID 泄露到用户界面

**现象**：聊天顶部账号选择器可能显示 `Facebook • fa-...`。部分能力说明与媒体中心也会在账号名称缺失时回退显示内部 ID。

**根因**：`accountRouteIdentity()` 最终回退到候选列表第一项；候选列表包含 `authAccountKey`、`adapterAccountId` 和数据库账号 ID。其他页面直接使用 `sourceAccountIdentity || sourceAccountId`。

**修复**：

- Facebook 身份优先顺序保持为公共主页名称、实时页面名称、用户名称、显示名称和用户名。
- 内部标识只允许进入诊断详情，不再作为普通界面回退值。
- 名称尚未同步时统一显示“账号名称待同步”。
- 能力矩阵、媒体中心和操作确认对话框同步去除 `sourceAccountId` 回退。

### FIX16-002｜慢本地模型被过短超时误判故障

**现象**：部分本地模型能够完成任务，但生成速度较慢；全局默认 90 秒、会话分析 120 秒、回复基准 90–150 秒会误判模型不可用。

**根因**：超时散落在调用方，模型路由只保存 `maxTokens`，没有保存任务超时；队列预算和真实执行预算也未由同一策略统一。

**修复**：

- 新增 `TIMEOUT_LIMITS` 与 `normalizeTimeoutMs()`。
- 快速回复最低 180 秒；深度回复、媒体分析、语音任务最低 240 秒。
- 标准任务最高可配置 900 秒；深度/媒体/语音最高可配置 1200 秒。
- AI Gateway 取“路由配置值与调用方值中的较大值”，再按任务边界规范化。
- 队列等待预算不得短于真实模型执行预算。
- 模型调用结果和尝试记录写入本次有效超时，便于诊断。
- Ollama 全局默认超时由 90 秒提高为 180 秒。

### FIX16-003｜AI 工作台无法按任务配置超时

**现象**：只能选择主模型、备用模型和输出上限，无法为慢模型单独设置任务时限。

**修复**：

- “任务编排中心”每条路由新增“超时（秒）”。
- 前端按任务展示最小值、最大值和 30 秒步进。
- 保存时以毫秒写入模型注册表。
- 路由真实测试采用当前路由超时，并给 HTTP 请求额外预留 60 秒，不会在模型仍运行时先被前端中断。
- 六列路由布局同步调整，避免新增字段造成挤压或错位。

### FIX16-004｜翻译永久停留“等待中文翻译”

**现象**：翻译服务发生非预期异常后，任务记录会失败，但消息数据库可能仍是 `translationStatus=pending`；前端也没有收到用于清理自动翻译队列的 DOM 事件。

**根因**：

- `drain().catch()` 只更新任务状态，没有回写消息状态。
- Electron 桌面事件更新了消息列表，却没有转发 `message:translation-updated` 给双语体验运行时。

**修复**：

- 新增异常结算：回写 `failed`、错误码、错误说明、源文本哈希和目标语言。
- 保留上一次成功译文、模型和时间，失败不会抹掉已验证结果。
- 用户主动取消仍保持 `cancelled`，不会被错误结算覆盖。
- 桌面事件处理后派发同名 DOM CustomEvent，立即清理前端等待集合并显示失败/重试状态。

### FIX16-005｜翻译任务长期运行内存增长

**根因**：翻译服务 `jobs` Map 没有终态清理。

**修复**：默认最多保留 500 条任务记录，创建新任务前优先淘汰 success/failed/cancelled/skipped 终态任务，不删除排队或运行中的任务。

### FIX16-006｜分析、媒体和模型验证超时不一致

**修复**：

- 会话理解统一采用任务超时策略。
- 真实会话分析前端请求预算调整为 300 秒，后端模型预算 240 秒。
- 本地视觉媒体理解由 120 秒提高为 300 秒。
- 云模型最小文本/视觉验证由 90 秒提高为 180 秒。
- 回复大脑基准按模型规模使用 180–360 秒基础预算，并允许观测延迟动态扩展到 600 秒。
