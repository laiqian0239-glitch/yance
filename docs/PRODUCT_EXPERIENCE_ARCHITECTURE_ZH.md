# 言策 Windows 产品体验架构基线

## 产品定位

言策是面向德国和欧洲客户的多平台、多语言、关系型 AI 沟通工作台。

核心用户旅程只有一条：

```text
收到客户消息
→ 识别平台、账号、联系人和语言
→ 显示原文与中文理解
→ 加载客户事实、关系轨迹和当前上下文
→ AI 生成客户语言候选与中文回译
→ 用户调整语气并确认平台、账号、语言和附件
→ 真实发送并记录结果
→ 学习用户修改和客户反馈
→ 更新客户档案、关系洞察和下一步建议
```

## 五个核心空间

1. **会话**：消息、翻译、媒体、发送、AI 候选和实时互动。
2. **客户**：搜索、联系人身份、客户档案、标签、归档和事实。
3. **关系**：关系轨迹、阶段、机会、风险和下一步。
4. **AI 工作台**：模型路由、Persona、学习治理和效果评估。
5. **系统**：账号连接、主题、通知、数据、诊断、备份和恢复。

搜索联系人是全局能力和客户中心模式，不是与客户中心重复的页面。

## 页面职责

- 会话页只显示当下沟通需要的信息。
- 客户档案保存长期事实与人工确认资料。
- 关系轨迹记录按时间发生的事件。
- 关系洞察负责综合判断和下一步。
- AI 回复大脑负责本次回复，不复制客户档案。
- AI 工作台负责模型和规则治理，不复制日常聊天。

## 三栏会话结构

- 左栏：搜索、筛选、会话、未读、归档、平台和快捷操作。
- 中栏：原文/中文、媒体、消息菜单、输入、附件和发送状态。
- 右栏：中文理解、意图风险、策略、外语候选、中文回译和发送确认。

## 双语规则

给用户理解的关键内容默认提供中文；给客户发送的内容保持联系人语言。统一数据字段：

```text
sourceText
sourceLanguage
translatedZh
translationStatus
translationModel
translatedAt
```

支持中文、原文、双语三种显示模式。

## 状态真实性

任何“在线、已启用、已学习、已同步、路由健康”状态必须读取真实权威数据源。禁止用界面开关数量代替后端可用状态。

## 主题与组件

所有页面共用按钮、输入框、卡片、弹窗、菜单、状态、空状态、图表、滚动条和标题栏组件。结构色、字号、间距只来自语义 token；业务样式不得写死结构颜色。

## 失败与恢复

每个错误必须说明发生了什么、是否影响数据、是否自动重试、用户该做什么、能否撤销恢复。产品必须自动处理旧后台进程、断线、模型加载、翻译失败和发送重试，不能把 PowerShell 当成正常用户流程。
